# 下一阶段开发顺序

先保留并验证原系统完整的一键批阅流程，再优化操作效率、连通身份和云端持久化，随后接入扫描。学生互批作为独立项目另行实施。每一项在独立开发环境完成，正式 Daily 和 WriteAscend 不作为调试数据源。

| 顺序 | 工作 | 完成判据 |
| --- | --- | --- |
| 1 | 建立安全版本基线与合成报告样例 | WriteAscend 审计提交可回查；Daily 源码按允许清单版本管理，不包含 `.env`、账号库和媒体；样例覆盖保留清单 |
| 2 | 保留原完整教师流程并模块化构建 | 题目、标准、范文、名册、上传、一键 AI 批改、暂停继续、核对编辑、导出与分析可用；不得用历史导入页替代产品入口 |
| 3 | 新建 Workers/D1/R2 测试工程 | 持久化任务与报告、服务器密钥、身份保护、私有文件访问可验证；没有匿名生产接口 |
| 4 | 实现 Daily 身份桥接与学校班级授权 | 授权码、PKCE、回调白名单、停用与撤销、教师范围、游客限制、既有登录回归通过 |
| 5 | 接入受限名册与历史迁移预检 | 2,327 名当前在用学生可完整分页对账；同名只显示候选；旧完整备份上传前剔除凭据；重复导入去重 |
| 6 | 跑通教师发布与 Daily 摘要回传 | 教师确认版可发布到本人学生；事件失败可重试、不重复；旧 writing 自评与 Journey 数据不覆盖 |
| 7 | 实现个性化写作单与手机扫描 | 真实 A4 打印、复印、单页和多页、打乱顺序、重扫、拿错纸、无二维码和弱网均有明确处理 |
| 8 | 接入识别与原有批改策略 | 识别错误与作文错误区分；保留原评分与输出；重试不覆盖人工修改；首个班完整完成一次作业 |

第 2 项建立完整教师功能基线，第 4 项建立身份边界，是后续独立学生互批项目接入的前置条件。互批通过接口使用教师任务 rubric 的简化学生描述，不另建不相干的评分标准；另设评阅分配、反馈证据、作者回应和二稿，单独验收。

正式切换前仍需完成：实际 iPhone/Android 浏览器验收、真实手写样本识别验证、教师旧浏览器数据迁移、Cloudflare 配置预检和还原演练。本阶段不把这些未执行项目计为通过，也不需要教师重新批准已经授权的普通开发步骤。
