# 限定后台工作授权

## 操作边界

交互登录继续采用 15 分钟授权，用于教师浏览、编辑、提交与发布；后台工作使用独立机器接口，不能当作浏览器登录、名册读取或报告发布凭据。无需教师额外填写密钥或打开新的开关。

学校任务在提交时固定运行、任务、学生成员、班级、稿次、原稿摘要、模型输入摘要、模型配置版本及批阅管线版本，整个管线共用这一个工作授权。普通模型任务（原工作台、图片检查和 OCR 共用的队列接口）只获准完成一个固定任务和请求摘要；不能拿它创建别的任务。原个人工作台尚由前端协调后续修复/润色步骤，页面恢复后才会发起尚未提交的步骤，不能把单个请求后台执行称为整套个人管线已在服务器自动完成。

工作引用只在 Worker 的私有 D1 与 Daily 服务间使用。浏览器只取得进度等元数据，不能取得工作引用、来源 Cookie 或机器凭据。Daily 仅存操作标识和摘要，不存作文内容、模型原始输入或供应商密钥。来源引用继续使用已有 Daily 本机 AES-GCM 加密密钥，不新增需教师配置的凭据。

## 生命周期

1. 提交操作前验证当前教师登录、班级权限、固定原稿和模型。Daily `work/authorize` 再核验来源，并保存不可变范围及当时的班级/教师授权版本。
2. 授权最多 24 小时，且不超过来源会话自身到期时间。正常 15 分钟交互授权到期或清理其旧记录，不取消这项已批准的工作；关闭页面也不取消。
3. 每个需要付费的模型步骤发送前，重新核验本机来源会话、账号和角色、工作到期/撤销状态；学校运行还核验当前班级权限及授权版本。图片和请求准备完成后才进行最后核验，避免大图读取扩大权限核对到发送之间的间隔。
4. 账号停用、角色变化、源会话失效、班级停用或授权版本变化都会阻止后续调用。被撤销后重新授权班级不自动复活旧工作；教师须在当前登录下明确继续，取得限定原运行的新授权。
5. 暂停会阻止本地运行和旧工作授权；继续会复用已保存步骤。已成功的模型响应不重算，已发送但结果不明仍停在待确认状态，不因工作授权更新就自动重试。
6. Worker 主动退出在同一 D1 事务内记录原登录撤销并删除会话，再通知 Daily。即使 Daily 暂不可用，后续发送也会被本地记录阻止。Daily 的来源退出钩子同时按来源摘要撤销工作，即使其父交互授权已被清理。退出仅清除相应登录/来源的权限，不影响另一设备独立来源的合法工作。

已发出的供应商请求无法召回，返回结果继续私有保存，方便重新登录后恢复；这不产生第二次请求。权限核验与外部 HTTP 发送无法构成跨系统原子事务，因此不声称能撤销已经开始的调用。

## 幂等与恢复

工作范围通过规范化摘要固定，重复授权请求返回同一个引用；同编号不同范围拒绝。Worker 按教师、操作种类和请求编号生成稳定运行/模型任务 ID，授权回执丢失后可复用同一范围，不会因为重试生成另一份授权或模型任务。未成功落入 Worker 状态的孤立授权不能自行执行，受同一到期时间限制。

已有队列配额与原子入队仍生效；普通任务在申请授权前预检额度，最终仍由原子 SQL 决定。Daily 每个账号滚动一天最多接受 10000 项工作授权，防止异常提交无限累积。授权到期需要当前教师登录继续，不自动延长或扩大范围。

新增 Cloudflare 迁移 `0011_background_work.sql`：运行/模型任务的工作引用与到期时间，以及本地登录撤销表。迁移前的旧任务保留原授权路径；旧学校运行明确继续后采用新工作授权。新任务要求 Daily 已安装 `writing-work.mjs` 与相应机器接口，版本不匹配时停止并提示连接检查，不静默降回 15 分钟后台权限。

实现已在本地验证；正式环境还需应用迁移、核对来源退出/角色变更的真实路径和真实账号会话时长。整体发布、模型配置、真实设备、学生二稿与独立互评仍按总目标继续。
