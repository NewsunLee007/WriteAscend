# 教师写作任务、评分标准版本与授权名册

本阶段在原教师界面增加“写作任务”。原一键批改、上传、暂停继续、报告编辑、归档和导出继续使用；创建正式任务不是使用私人批改功能的前提。学生互批仍为独立项目。

## 教师流程

1. 在原快速批改或完整工作台准备题目、评分标准和输出设置。
2. 打开“写作任务”，输入名称，选择 Daily 已授权的学校班级，保存草稿。没有班级权限时可以先保存私人草稿。
3. “用当前设置更新草稿”建立新的不可变题目/评分标准版本。旧版本可通过接口读取；已建立的任务不接受覆盖标准，修改后应另建任务。
4. 预览学校名单，按姓名、班级、学年或身份短编号搜索，核对后确认建立任务。系统重新读取名册，发现变化时要求重新预览。
5. 在没有当前作文的批次中载入任务，恢复题目、原 rubric、难度及打印/CSV 设置，并将已确认的学校名单带入原班级工作流。既有本机班级继续保留。
6. 可查看任务名单、关闭任务或重新开放。关闭不会删除学生或评分标准版本。

当前已有作文时，载入任务会被阻止，避免旧报告显示新题目或标准。先保存结果，再到完整工作台“导入作文”中清空重选。后续需要完善手机的新批次切换流程及多批草稿管理，不能声称目前已支持无损的任意批次切换。

## 数据和权限

迁移 `0004_writing_tasks.sql` 增加 `writing_tasks`、`rubric_versions`、`task_members` 和操作去重记录。D1 保存任务状态、所属教师、版本、班级快照及学生；私有 R2 保存完整的题目、rubric 和配置。每个 criterion 保留原编号、名称、分值、说明及扩展字段，不用新评分方法替换原方法。

学校目标班级只能来自当前 Daily 会话中同时具有 `roster.read` 与 `writing.manage` 的授权。名字相同的本机班级、旧 JSON 中的学生 ID 和浏览器自行提交的名单都不能成为正式任务成员。创建草稿时检查权限；预览和确认时再次检查来源身份、班级目录版本和授权版本。

名册适配器按不可变 subject、当前在用状态、源班级、年级和有效成员关系过滤。每次返回完整过滤名册的 snapshotHash；分页期间摘要变化会中止。确认建立时重新读取并比较整个预览摘要，然后原子保存任务状态和成员快照。空名单、重复 subject、来源身份变化、失去班级权限都不能建立任务。

同名学生保留不同 provider/subject 和任务成员 ID。原工作台按名字匹配时须唯一，不能取同名第一条；号码重复也不作为唯一身份。导入学校名单不推测原学号，保留教师已有的本机号码和别名。修改报告姓名后若变为不确定归属，会撤下当前记录的旧学生档案关联，报告本身仍保留。

任务创建、草稿更新、名单确认和状态切换均使用 requestId 去重与版本检查。创建 ID 由所属教师和请求编号摘要确定，并发重试不会产生两个任务。客户端同一操作的请求编号保存在按账号隔离的 sessionStorage 中；不据此承诺关闭浏览器后自动完成未提交的任务草稿。

## 与批改结果的关系

`sourceTask` 记录教师载入的模板来源，随本机草稿和原报告存档保留。它目前不是服务端确认的 submission/grading_run 绑定。教师之后修改题目或标准，实际报告仍保存自身使用的内容，不能仅凭 sourceTask 就把成绩发布给学生。

正式稿次、原稿与身份确认、评分输入摘要、教师发布以及 Daily 回传尚需后续实现。任务“已建立”不代表学生已收到作业或报告。同名待核对结果仍需后续二维码或人工身份选择处理，不能直接自动发布。
