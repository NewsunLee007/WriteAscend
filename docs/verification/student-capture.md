## 功能与检查

`npm test` 共 71 项通过，生产构建及 Worker dry-run 通过。TAP 见 [student-capture-tests.tap](student-capture-tests.tap)。新增检查覆盖：

- 姓名中文、全拼、拼音首字母、大小写、复姓、姓氏读音、多音字、全角班号及姓名/班级组合检索；同名保留全部候选，不自动选第一条。
- 拍摄前身份快照与二维码的学生、稿次、页码冲突检测；多页缺页建议。
- OCR 精确姓名和可见班级匹配；班级不符、重名、相似错字、多位学生及离校学生不自动确认为唯一归属；纸面学号不等同于系统身份短编号。
- 批改和 OCR 模型默认复用、独立选择、用途过滤与纯文字排除；服务端在模型任务入队前拦截文字型号图片请求，未产生排队任务。
- 模型帮助链接和能力配置校验；JSON 响应解析不执行图片或模型中的指令。

## 实际本地服务与 390px 浏览器

`student-first-capture.cjs` 验证拍摄前首字母检索、同名班级/编号显示、预选关联、收齐回执前不能进入下一位、二维码冲突必须明确选择、断网照片刷新后保留原身份、多页补齐后继续下一位。手机预览已目视检查，无页面横向溢出。

`model-ocr.cjs` 使用两个合成图片模型和一个文字型号，验证：

1. 文字和 OCR 专用型号不作为拍照批改选项；OCR 选择刷新后保留。
2. 连接检查只上传系统生成的测试图片，每个不同模型各调用一次；官方帮助链接可用。测试供应商的正确识别响应为模拟结果，不代表真实模型质量。
3. 多张无二维码照片全部先进入 IndexedDB，再开始联网识别。
4. 第一张识别进入队列后刷新，重新打开收作业会复用原模型、原图与请求编号；两张照片总共各调用一次，没有因刷新重复调用。
5. 模型只读出纸面姓名和班级，本机与任务名单匹配，尚未教师确认时不会生成已收稿次。
6. 已无法确认供应商处理结果的识别不会自动重算；取消明确的重新识别确认后不产生新任务。
7. 教师确认后写入真实任务成员及核对说明；收取直接复用识别时的私有原图，不重复上传。

原 `writing-collection.cjs` 回归覆盖二维码、多页、重复与替换、弱网、相机关闭与退出清理。原完整入口、快速入口、批量批改和云端批改检查覆盖原报告六个主要栏目、人工编辑与导出、暂停重试、刷新复用同一模型任务及不同教师隔离。

逐项结果及脚本摘要见 [student-capture-browser.json](student-capture-browser.json)。本轮只修改 WriteAscend 与合成 QA 来源，没有修改实际 Daily 集成源码或正式运行配置。
