# 手机扫码收作业与稿次输入

本功能在教师已有任务下收取作文照片，并保持原一键批阅、报告编辑与导出流程。学生互批仍是独立项目。收齐页面与已完成批改分别记录，不把扫描成功当作已经批阅或发布。

## 教师使用

已建立任务可从任务列表打开“扫码收作业”；载入任务后，工作台提供同名快捷入口。入口会重新读取真实任务状态。关闭扫描页返回原工作台或任务列表，不替换当前批改设置或作文。

- **连续拍照**：优先使用后置相机，每次拍一整页，拍完可继续取景。关闭相机、关闭扫描页或切到后台会停止相机；相机不可用时可使用系统拍照或相册多选。扫描过程中也可关闭面板，已存照片留在本机。
- **二维码定位**：自动显示任务学生、班级、稿次和页码。教师核对纸面信息后，可逐页上传，或一次确认并上传本批清晰的二维码页面。分辨率提醒、重复页、身份更正和未识别页面不自动混入批量收取。
- **无二维码**：明确选择任务名单中的学生、稿次、页码及总页数，填写至少 5 字的核对说明，再确认照片清晰度与纸面身份。同名选项显示班级及身份短编号。
- **拿错纸**：二维码姓名与纸面不符时改为手工核对，保留原检测到的纸张编号及更正说明；不会改写原写作单身份。已识别的其他任务页面不能在当前任务自动接收。
- **重扫与替换**：同一页相同照片不重复计数；不同照片需要明确核对旧页并确认替换。每次替换保留旧照片引用、页面版本及当时稿次输入。
- **收取情况**：按稿次查看已收齐、缺页、未收及当前页面；可核对后说明原因移除错收页。移除保留历史，当前稿恢复缺页。照片的上传回执与当前稿收齐情况分别查看，旧回执不会重复增加页数。

一张照片检测到多个写作单二维码时要求重拍，包括同一张纸的两份复印件；不能将其直接按一个页面批量收取。此检测仍需真实纸张实测，不能承诺识别所有遮挡或模糊情形。未识别二维码不等于已证明照片只有一页，人工确认仍需核对整张照片。

## 弱网与本机照片

照片先保存到按账号、任务隔离的 IndexedDB，之后本机识别二维码；定位和上传需要当前服务可用。支持在已打开页面内断网保留照片，联网后继续核对。已明确确认但未完成的上传在网络恢复时继续；网络恢复恰逢其他操作时延后执行，避免丢掉恢复信号。

手机仅解码当前照片的缩略预览，可在预览框内放大平移；原稿照片与预览分开保存，图片准备中断后可继续识别。

图片上传到私有资产存储后，收作业接口返回回执才计入已收。回执请求发送前保存同一个操作编号和内容；响应丢失、刷新或重试沿用原请求。服务端重复请求不重复建稿、不重复计页。关闭浏览器或锁屏不保证继续上传；离线重新打开整个网站仍需网络，当前没有离线应用外壳。

常规 JPG/PNG/WebP/GIF 照片在 12 MiB 以内保留原文件上传；过大或浏览器可读取的其他图片转换为整页 JPG，并提示核对清晰度。未裁切原稿区。不能读取的图片标为需重拍，不进入自动批量收取；不承诺所有设备都能直接读取 HEIC。

本机缓存可逐张移除，已收页面不会因此从服务器撤回。显式退出有未确认照片时先说明清理后果，成功退出后清理当前账号的扫描缓存，并通知其他页面退出。缓存清理同时轮换代次，旧页面或旧上传的异步写入不能把清理过的照片恢复回来。登录自然过期保留待传照片，重新登录同一账号后继续处理。

## 服务端数据

迁移 `0006_writing_collection.sql` 增加以下记录：

| 表 | 用途 |
| --- | --- |
| `writing_submissions` | 同一任务、同一任务成员的一份作业，稳定 ID，不按姓名合并 |
| `writing_drafts` | 初稿/二稿等稿次编号、固定任务和 rubric 版本、总页数、当前输入版本及收取状态 |
| `submission_page_versions` | 每次确认的页面、私有资产及照片摘要、纸张编号、二维码/手工方式、说明、操作人和时间 |
| `writing_draft_inputs` | 每次页面变化的不可变有序输入清单与摘要；旧版可单独读取 |
| `writing_page_claims` | 当前照片的唯一稿次/页码归属，防止同一文件被静默分给另一学生或另一页 |
| `writing_collection_operations` | 请求去重与回执，移除操作保留原因和旧页面编号 |

稿次编号和输入版本不同：例如第 1 稿收到第二页后补齐第一页，仍是第 1 稿，但输入版本从 1 变成 2。替换或移除再建新输入版本；旧输入及照片引用不覆盖。

输入摘要绑定真实任务成员的 provider/subject、班级、任务标准版本、rubric 摘要、稿次、页数及按页码排序的页面引用和确认依据。二维码模式的成员、稿次、页码来自服务端写作单，客户端伪造同名字段无效。人工更正需要显式任务成员及说明，不从模型输出姓名推测身份。

写入前核对本人任务、当前班级 `roster.read` + `writing.grade`、来源身份及角色、学生任务关系、任务状态和私有原图实际存在。所有请求仍受同源与当前工作区保护。事务内比较任务版本、在用写作单、稿次输入版本及当前照片归属；并发页面不互相覆盖。已有收取页面时，补打不能改变本稿总页数；可使用其他稿次，或明确移除页面后重新核对。

## 接口

| 接口 | 内容 |
| --- | --- |
| `GET /api/tasks/:id/collection?draftNumber=1` | 当前获批改权限的任务成员收取情况，100 人分页 |
| 同路径加 `memberId` | 本人任务中该学生的当前稿次输入及在用写作单页数 |
| 同路径再加 `revision` | 读取该稿次某次不可变输入 |
| `POST /api/tasks/:id/collection`，`action=collect` | QR 或显式人工核对后收取，返回实际输入版本、页数及回执 |
| 同路径，`action=remove` | 按当前页面版本及明确原因移除当前页，保留全部历史 |
