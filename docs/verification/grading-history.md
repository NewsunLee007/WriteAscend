# 教师报告历史与重新批阅验证

2026-10-17。继续保留教师一键批阅、修改、发布、导出与分析，在同一任务稿次内补齐批阅历史。使用本地真实 Worker/D1/R2/Queues、合成学校账号与模拟模型，不代表真实手写模型效果或正式上线。

## 已实现

- 每个稿次可回看所有 AI 批阅运行，每次运行可查看原始 AI 报告与历次教师修订。运行和修订分别每页 20 条，通过游标加载更多，不截断为“最近若干条”。读取检查教师归属和当前班级权限，不下发私有 R2 对象地址或密钥。
- 历史报告只读，可与最近完成的报告并排对照；手机端按顺序展示两份完整报告。每份标明模型、原稿输入版本、评分标准版本及旧原稿状态，可查看该次运行固定的手写原稿。
- 历史内容可另存为本报告的新教师修订，原有版本保留。保存使用当前修订号检查，其他设备更新会拒绝覆盖；同内容不创建重复修订并给出提示。该操作不调用 AI，也不更新已发布给学生的独立快照。
- 老师从报告页主动选择“重新 AI 批阅”，选择已配置模型、填写原因并点击“确认重新调用 AI 批阅”。支持主动更换模型；新运行保留前一次运行引用与理由，使用当前已收齐输入。原稿变化、旧运行非最近、跨学生或尚未完成的运行均拒绝重批，未完成运行使用原有继续处理入口。
- 并发点击只建立一个新运行；结果不明的原模型步骤仍不能自动重试。普通重复提交复用当前相同输入/模型的最近运行；更换模型不能借普通提交隐式重算。正在重新批阅时，旧报告仍能通过历史查看，学生继续查看老师此前发布的版本。
- 班级列表保留主要“查看报告”操作，历史/重新批阅放在报告页，避免手机每行堆叠多个按钮。尚未生成新报告时，列表提供旧批阅历史入口。
- 新增 `0010_grading_history.sql`，按教师/稿次/时间建立历史读取索引。本地 QA 数据库已应用，远程数据库未应用。正式启用应从当前已应用版本迁移至 0010，不能修改已应用迁移文件。

## 验证

- `npm test`：106 项通过。本轮新增 4 项测试覆盖 41 个报告修订、24 次运行的完整分页、原始 AI 版保留、恢复为新修订、旧发布快照保留、按操作复用、并发新运行保护、主动更换模型及跨学生/旧输入/未完成运行拒绝。
- `npm run build` 和 `npm run worker:check` 通过，后者仅 dry-run，没有远程部署。
- [浏览器结果](grading-history-browser.json)：教师、学生与同名学生三个独立上下文，验证历史只读、版本对照、另存新修订、重新 AI 批阅、重新批阅期间的旧报告访问及学生版本保持。沿用完整发布/重新发布/撤回、Daily 摘要/回执修复和学生打印流程。
- 原快速批阅与完整教师流程的浏览器回归通过；完整流程保留 6 个报告栏目和保存能力，脚本摘要及结果包含在同一浏览器记录中。
- 首次批阅调用 1 次模拟模型；查看、对照、恢复和 Daily 补发均不增加调用；明确重新批阅再调用 1 次。375/390/768/1440 宽度检查无页面或历史容器横向溢出，手机与桌面截图已目视检查。
