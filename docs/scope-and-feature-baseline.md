# 教师作文批阅升级范围

用户于 2026 年 10 月 16 日明确：以原 GitHub 作文批阅系统的完整功能为基础全面优化，核心是帮助教师借助大模型简单高效地一键批阅作文。Our Teacher 是操作设计参考。学生作文互批是独立新项目，另行设计和实现。

## 产品范围

教师端默认进入布置与批改流程，而不是历史报告导入页。原有功能不是仅保留导出栏目，须保留从题目识别到批量批改、结果修改、档案与班级分析的完整链路。

教师工作的主要操作顺序保持：选班与年级、设置或复用题目和评分标准、拍照或批量上传作文、一键批改、教师核对与导出。沿用设置可减少重复操作；复杂设置收起但保持可用。手机端优先考虑上传、连续扫描、批改进度和快速核对。

## 必须保留的功能基线

| 原有功能 | 处理原则 |
| --- | --- |
| 多模型 API 地址、模型与参数配置 | 保留可配置能力，云端阶段将密钥转至服务器；过渡版保留原调用方式 |
| 写作题目图片识别、文字核对、要点分析 | 保留完整步骤，可在简洁流程中复用历史任务 |
| 评分标准手动设置、文件导入、AI 生成 | 保留自定义维度、总分、字数、年级、时态、严格程度、难度与备份恢复 |
| 参考范文生成、双难度与英文难度控制 | 保留，升级稿和标准范文仍分别显示 |
| 班级、学生、序号、别名与批量名册导入 | 保留操作能力；后续与 Daily 唯一 ID 对接，冲突须核对 |
| 批量图片上传、追加作文、逐份查看 | 保留；增加连续拍摄、文件识别状态、失败重试和重复检测 |
| 单份与一键批量 AI 批改 | 作为核心入口；保留暂停、继续、重试、结果解析和难度修复 |
| 原文、总分、分项、总评、亮点、纠错与优化 | 保留现有结果和纸张视图，教师可核对修改 |
| 升级稿、标准范文、原稿和题目显示选项 | 保留，不按 Word 参考文档缩减 |
| A4 打印、单份与批量 PDF、CSV、JSON | 保留原设置、历史记录及恢复；具体格式见导出保留清单 |
| 学生档案、历史结果、班级综合分析 | 保留；逐步从浏览器存储转为云端可同步数据 |

## 对已经开始的开发作出的修正

之前的报告导入实验页不再作为应用入口。主入口已恢复为原系统完整 TeacherApp；评分与提示逻辑从原 HTML 抽取保留。原始 HTML 保存在 `legacy/index.html` 作为比对基线。

当前模块化先改变构建和代码组织，后续每项产品改动都需对照上表验收，不能因为界面简化而删掉现有能力。报告兼容工具仅作内部验收和迁移辅助。

## 学生互批项目边界

学生互批单独开发、单独页面与发布流程。共享统一身份、写作任务引用、教师发布的 rubric 版本和稿次引用，通过受控接口关联。教师可以选择把作文发布到互评项目，但默认的一键批改不依赖学生互评，也不把互评配置强塞进每次教师批改。

互评项目另行实现匿名分配、证据式反馈、评阅示例训练、作者回应和二稿修订；原 Word、AI 升级稿和学生自主二稿保持来源区分。其身份权限与教师端同样需要验证，不能先做一个展示性的互评菜单替代真实流程。
## 最新补充：手机收取、学生结果与模型配置

- 支持先按姓名或拼音首字母选学生，再拍照上传并继续下一位；预选信息逐张固化，同名不得取第一条。
- 无二维码照片由视觉模型提取纸面身份，并与任务名单生成候选；同名或冲突须核对，不能凭模型姓名创建或改绑学生账户。
- 正式报告绑定 Daily/WordUp 稳定学生身份，教师核对发布后由学生自主查看；照片收取、AI 运行、教师核对与发布分别记录。报告运行绑定、教师按版本发布/撤回与学生自助查看已完成本地联调；Daily 摘要投递与回执修复也已完成本地联调；正式启用尚未完成。
- 模型默认复用，需要时单独设置 OCR，提供连接/图片检查与帮助。个人模型服务端加密托管已完成本地实现，密钥不进入浏览器存档或 Git；真实模型验收尚未完成。
- 原教师一键批阅、主要报告内容及导出继续保留；学生互批仍是独立新项目。

## 最新授权：界面与报告可以全面重新设计

用户明确允许抛弃最初 GitHub 项目的界面，并全面优化最终批改报告。功能保留不再意味着保持旧布局、色彩、纸张卡片或组件实现。教师仍以大模型一键批阅为主线，保留题目/标准设置、原稿、分项与总分、总评、亮点、纠错、内容优化、改写示范、参考范文、教师修改、导出和分析能力；可重新组织呈现与交互。Word 参考继续作为内容检查依据，不作为固定视觉模板。学生互批仍单独建设。

## 自主二稿的当前边界

独立互批的 Daily 授权和账号入口已完成本地验证，采用自己的 Worker、数据库和 Cookie；教师原一键批阅继续独立运行。实际互评材料、轮次和评阅页面仍待实现，见 [独立登录](peer-review-auth.md)。

后续进展：教师材料准备、固定来源快照、独立导入和回执已完成本地验证，见 [材料交换](peer-materials.md)。当前仅原任课教师可读取导入材料；学生轮次授权、实际互评和同伴反馈二稿尚未完成。

学生从本人已发布反馈开始自主手写二稿，按教师原标准说明修改、上传新稿和反思；教师核对收取后沿用原一键批阅。该流程已完成本地实现与合成浏览器验证，见 [学生修订](student-revisions.md)。它属于既有反馈的自主修订，不代表同伴互批已完成；互批仍另建项目，以接口共用身份、任务、评价标准和稿次。第一稿、教师发布快照与学生真实新稿分开保存，AI 改写示例保持原有来源标记。

独立互批工程现位于 `apps/peer-review`，有独立包与测试，不导入教师批阅页面/核心，也未进入默认教师流程。已实现的领域规则与待完成的授权、来源快照、轮次持久化和页面分别记录，见 [互批接入方案](peer-review-integration.md)。互批可先于 AI 批阅，后续二稿需支持经核验的同伴反馈依据，不能把教师 AI 报告发布当作必需前置条件。
