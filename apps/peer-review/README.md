# 学生作文互批（独立应用项目）

此目录是独立项目，有自己的包、测试和部署边界。它不导入 WriteAscend 的教师页面或批阅实现，也未把互批开关加入教师默认一键批改流程。领域核心、独立 Daily 登录、账号入口、教师确认材料的来源交换和导入已完成本地联调。互评轮次、实际评阅页面及独立部署继续开发，不能称为已上线的互批产品。

## 当前可执行检查

```sh
npm ci
npm test
npm run check
```

仓库根目录也可执行 `npm run peer:test`、`npm run peer:check`，或 `npm run test:all` 同时检查原教师系统和互批核心。包锁文件独立保存，当前开发可向上复用仓库已安装的开发工具；不要求教师端增加运行依赖。

## 核心实现

- `src/core/rubric.ts`：保留当篇任务/标准版本引用、原分项名称与分值、总分、字数及严格设置、时态和年级；逐项映射成学生可读提示。启用前需老师确认；未知维度须写明自定义描述。只提供文字材料时，书写卷面保留给老师核对。四档是“达到、部分达到、待改进、不确定”的课堂支持设计，不转换为老师分数，也不宣称是经验证的新考试量表。
- `src/core/allocation.ts`：最多 300 人，每人 1–5 份且少于本轮人数。使用二分图流量匹配，使每人评阅数与每篇被评数都等于选定份数，禁止自评、重复稿件和老师排除的关系。不可满足时整体失败，不返回残缺分配。本轮私有随机种子固定后可重现；不承诺自动避免相互评阅或所有跨轮重复，需明确排除的关系由老师设置。
- `src/core/feedback.ts`：使用冻结材料文字与标准版本；引用必须精确匹配原文位置。至少一处有原文依据的优点和一条可操作建议；给出负面档位需同维度建议，不确定需提问。作者逐条说明采纳、部分采纳、保留或提问的理由，采纳还须说明怎样修改。

这些是领域函数，不是认证接口。`teacherConfirmed/actor` 必须来自以后服务端核验的教师动作；hash 采用 SHA-256(JSON.stringify(冻结内容))，仅校验版本内容，不能替代身份授权。服务端须使用自己保存的冻结标准与材料，不信任浏览器上传的整份标准或自行计算的 hash。分配输出含私有身份对应关系，只能服务端保存，不能整批下发给学生。学生标准投影会去除确认教师的内部账号标识。

## 研究与适用范围

已核对教育部《义务教育英语课程标准（2022年版）》相关目标和评价章节、Cambridge A2/B1 官方写作表，以及同伴评价研究。来源、页码与改编边界见 [研究记录](../../docs/peer-review-research.md)。初中学生的任务描述必须由任课老师结合本班能力确认，不能把 CEFR 等级直接等同于年级。课堂描述为本项目改编，仍需学生试用及教师一致性核对。

## 接入顺序

1. 已本地接通 Daily 独立授权客户端、机器凭据和回调白名单；WordUp 原账号只在 Daily 核验，跨项目不共享浏览器会话 Cookie 或模型 Key。正式环境默认关闭，见 [独立登录配置](../../docs/peer-review-auth.md)。
2. 已本地接通 WriteAscend 经老师确认的最小文本快照、独立导入与回执。原始照片与报告不交给同学，身份对应只存服务端。当前机器通道仅支持原任课教师导入；学生访问授权尚未建设。见 [材料交换](../../docs/peer-materials.md)。
3. 独立数据库保存互评轮次、成员对应关系、材料、分配、评阅、发布/隐藏、申诉和作者回应。服务端按分配限制学生读取，来源停用/撤回需停止访问。
4. 学生完成示例训练，再提交真实反馈；老师可以处理异常及发布反馈。作者回应后经接口关联自主二稿（需增加同伴反馈依据类型，不能强制先有 AI 报告发布），学生互评分数不覆盖教师评分。
5. 完成实际服务端/浏览器/手机/权限和回滚验收，再配置独立 Cloudflare 测试资源与正式发布。

当前没有向正式账号库、学校目录或远程互评服务写入数据。具体接口边界见 [跨项目方案](../../docs/peer-review-integration.md)。

## 本地账号入口

```sh
npm run build
npx wrangler d1 migrations apply writing-peer-local-qa --env development --local
npm run worker:dev
```

Worker 使用 `127.0.0.1:8793`，开发 Daily 来源为 `127.0.0.1:8890`。Worker 本机秘密配置使用 `PEER_BRIDGE_SERVICE_TOKEN`，与合成 Daily 的互批机器凭据一致，不能使用原教师系统凭据。运行合成来源须在仓库根目录启动 `node scripts/qa/daily-bridge-sandbox.mjs`；其内存数据仅供本地 QA。单独 Vite 开发使用 5191，完整授权回调在 Worker 8793 验证。

`migrations/0001_peer_auth.sql` 和 `0002_source_imports.sql` 已应用本机独立 QA 数据库，后续结构修改新增迁移。Wrangler 中 UUID 仅为本地占位，没有远程互批数据库或生产绑定。首页显示账号与班级，`/imports/:exportId` 提供原任课教师材料预览、确认和回执恢复；实际互评任务管理尚未实现。

材料连接还需 Worker `SOURCE_ORIGIN`、`SOURCE_EXCHANGE_TOKEN`，对应 WriteAscend 的 `PEER_ORIGIN`、`PEER_EXCHANGE_TOKEN`。交换凭据单独配置，不能使用两应用的 Daily 凭据；正式环境尚未设置。
