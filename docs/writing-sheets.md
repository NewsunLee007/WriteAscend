# 个性化写作单与二维码身份

在“写作任务”中，对已建立且开放的任务选择“打印写作单”。本功能复用原任务题目、完整 rubric 和已确认的学校名单，不替换教师原有一键批阅、批改报告或导出。

## 教师打印流程

1. 选择任务班级、学生、稿次和每人页数。每批最多 100 人，每人 1–4 页，可按班分批。默认学校页眉为用户确认的“瑞安市新纪元实验学校”，可编辑；页眉文字只影响打印，不改变学生的学校归属。
2. 生成每名学生自己的 A4 写作单。每页包含姓名、班级、任务名单中的学期、身份短编号、稿次、页码、独立二维码、12 位校验编号、四角定位点和 22 行正文区。
3. 打开独立打印预览，选择 A4、单面打印、实际大小 100%，关闭浏览器页眉页脚，打印或存为 PDF。独立打印文档不受原报告的 PDF 配置与样式影响。当前说明页和学生页按单面顺序排列，不承诺自动适配双面打印的正反配对。
4. 预览包含一份完整任务说明与原 rubric 的各项分值和说明，可投屏或另行发放。长题目完整保留在说明页，并可跨页；学生写作页只放短提示。教师范文不印到学生写作单上。
5. 保留下载的 PDF 可再次打印同一张纸。重新签发相同学生、任务和稿次时，必须核对并确认旧码作废；旧写作单记录保留。另一稿次的写作单不会作废上一稿。

当前打印准备保存在当前浏览器标签页、按账号和任务隔离的 sessionStorage。请求发送前先保存随机码与操作编号，响应丢失时可“恢复上次写作单”，沿用同一次操作。恢复会再次核对权限及写作单是否已作废。关闭标签页后不能保证恢复；可用已保存的 PDF，或核对后重新签发。显式退出清除本站的写作单打印准备记录。

## 后台关系与权限

迁移 `0005_writing_sheets.sql` 增加 `writing_sheet_sets`、`writing_sheets`、`writing_sheet_operations`。一组写作单绑定当前教师、任务、任务成员、固定评分标准版本、稿次、页数与模板版本 `handwriting-a4-v1`。学生同名仍按不同任务成员 ID 生成，不按姓名合并。

二维码是 `WA1:` 加 32 个随机字节的 base64url 编码，不是登录链接，不含姓名、班级、口令或学生统一 ID。浏览器生成随机码并在打印时使用；服务端只保存 token 摘要及从摘要派生的纸面校验编号，不保存二维码原文。随机码只是页面定位信息，不能赋予读写权限。

同一学生、任务和稿次只保留一组在用写作单。签发采用任务版本、旧写作单 ID 比较和数据库事务；并发或网络重试不会生成两组有效写作单，错误的旧版本不会作废原码。操作编号复用于其他内容会拒绝。

接口均需要当前教师登录，写入要求同源及当前工作区标识：

| 接口 | 用途与额外限制 |
| --- | --- |
| `GET /api/tasks/:id/sheets` | 分页查看本人任务写作单，需要相关班级 `roster.read` + `writing.manage` |
| `POST /api/tasks/:id/sheets` | 生成或重新签发，重新核验来源身份与班级管理权限 |
| `POST /api/tasks/:id/sheets/resolve` | 按二维码或纸面校验编号核对页面，需要 `roster.read` + `writing.grade`；其他教师、其他任务、作废页、关闭任务均拒绝 |

扫码核对接口返回任务成员、任务版本、稿次、页码和班级，同时明确 `identityConfirmed: false`。找到二维码不能证明学生拿对了纸，教师仍需核对照片中的纸面信息。校验编号有碰撞时要求扫描完整二维码，不自动选第一张。
