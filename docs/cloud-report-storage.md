# 原批改报告的云端保存与恢复

云端存档接在原系统的“保存批改结果”之后。教师仍使用原批改、核对、编辑、导出与分析功能。保存时先写入原格式的本机记录，再将报告、当次评分标准和已关联原稿存入自己的云端工作区。学生互批不在此界面中。

## 保留范围

存档保留题目、评分标准、班级设置、学生档案、难度配置、打印与 CSV 设置、作文条目及完整结果。总评、优秀表达、逐句纠错、内容优化、升级稿、参考范文、人工评分和未知业务字段继续保留。服务端不重新评分。恢复云端版本时直接使用该版本的评分标准，不重新分配分项分值。

浏览器临时 Blob 链接和 API 配置不会成为云端数据。原稿以私有资源编号关联；跨设备恢复后，通过需要登录的同源接口读取。旧的姓名、学生编号和班级 ID 作为历史字段保留，不能据此获得学校名册权限。存档目前为教师私人记录，不等同于已发布给学生的成绩。

原本机归档、JSON 备份和 CSV 导出继续存在。JSON 不嵌入原图；云端原图编号须在所属账号登录后读取，不能承诺把 JSON 带到任意账号即可恢复图片。旧记录中已经丢失的临时原图也不能由云端自动补回。

## 老师的操作

1. 完成批改并核对后，点击原来的“保存批改结果”。同步进度与失败重试显示在云端存档栏。
2. 默认另存新记录；勾选“更新当前云端存档”才会为已恢复的记录增加版本。旧版本保留。
3. “云端存档”支持搜索、恢复、下载 JSON、查看历史版本和移入回收站。回收站支持移回。
4. 两台设备修改同一版本时，后提交的修改不会覆盖新版本；本机副本保留，可另存云端副本。
5. 断网时待保存内容与需要上传的图片进入 IndexedDB。重新打开同一工作区、恢复网络或点击重试后继续同一次保存请求。

正在批改或尚未接收模型结果时，仍可保留本机快照，但暂不建立云端报告版本。暂停并接收当前结果后重新保存，避免把未完成状态误作完整存档。

## 存储与一致性

`0003_cloud_snapshots.sql` 增加私有图片、存档头、不可变版本和保存操作记录。D1 保存状态、owner 与摘要；R2 保存原图与完整 JSON。客户端不能选择 owner。

图片按账号与内容摘要去重，接收上限每张 12 MiB，检查 PNG/JPEG/WebP/GIF 文件标记。模型调用携带私有资源编号，由队列在发送前校验所属账号并读取图片。旧的 data URL 输入继续兼容；一次模型输入的图片合计限制为 12 MiB。移动端自动压缩与裁切尚未完成。

每次保存使用固定 requestId；断网重试与刷新复用该编号。更新携带 expectedRevision，以 D1 原子批次完成版本检查、头更新及操作记录。R2 先写不可变对象，失败时不前移 D1 版本。并发输掉的 R2 对象不通过报告读取接口暴露，后续需补充孤立对象回收策略。

浏览器写入请求同时携带工作区摘要；服务端与当前会话核对。账号切换后，旧请求不能写入新账号。查询、版本、回收站与原图读取均检查 owner。回收站为软删除，暂不永久清理报告、版本或共享引用的原图。

## 部署与当前边界

当前仅在本地真实 Wrangler/D1/R2/Queues 环境验证，未向正式域名部署。部署前须按顺序应用 0001、0002、0003 迁移，并配置 Daily 桥接与模型密钥。

云端快照还不是正式写作任务。正式任务与评分标准版本、班级名册绑定、学生发布及 Daily 摘要回传仍需独立实现；不能把存档旧学生字段直接当作可信关联。教师其他设置及分析历史仍主要在本机，未实现全工作区自动同步。

验证范围见 [云端存档验证](verification/cloud-snapshots.md)。
