# 同伴反馈关联手写二稿

2026-10-17。本机已接通独立互批、学生手写修订、教师收取、原一键批阅与学生本人新报告的完整路径。不要求先生成 AI 报告；原教师反馈修订路径继续保留。尚未上线公网版本。

## 操作流程

作者在独立互批中逐条保存对当前已发布建议的回应与计划，然后选择“用这些建议开始手写新稿”。进入 WriteAscend 后使用本人学校账号登录，核对题目、姓名、班级和建议份数，再建立下一稿。交接链接只含轮次 UUID，不含学生身份、照片、服务凭据或可兑换登录令牌。

学生在修订页对照已核对的建议与自己的计划，按原教师标准说明实际修改，上传 1–4 页手写新稿并填写反思。建议、计划和实际改动分别记录；采纳计划不会自动当作已经完成的修改。学生提交后，由原教师核对归属、页序、实际修改及依据，收取为正常的下一稿，再明确点击原一键批阅、核对和发布。建立草稿、上传、提交和收取均不会自动调用模型。

已有基于教师反馈的可编辑修订草稿时，学生可明确确认将本轮同伴建议加入同一份草稿。原教师反馈版本、修改说明和照片保留；未提交前可加入，已提交或已收取的稿件不被静默改写。已有其他互评轮次依据时也不会自动覆盖。

## 依据与权限

WriteAscend 每次向固定互批来源发送自己刚核验的学生身份；独立机器接口不接受浏览器自报身份。互批服务再向 Daily 的 `round/author` 验证冻结参与者、当前有效学校成员、原教师持续授权、班级及授权版本。该接口仅接受互批机器凭据，不伪装或复活学生/教师交互登录，也不提供整班姓名映射。

返回的 `newsun-peer-revision-basis-v1` 只包含当前作者的来源原稿关联、标准摘要、已发布反馈版本与当前作者回应；不包含评阅人的身份、其他作者或教师内部确认标识。所有当前已发布建议都必须有匹配版本的作者回应。内容采用递归排序 JSON 键的 SHA-256 校验；单份依据最多 1,400,000 字节，不截断反馈。

来源端再次核对本人稳定账号、任务成员、原稿输入版本、教师标准和有效分享。新增迁移 `0015_peer_revision_basis.sql` 保存依据类型、轮次及不可变依据快照/摘要，并扩展修订版本记录；原数据默认仍为教师反馈依据，已存在记录不改写。迁移只应用本机 QA。

建议隐藏、退回、改版、作者计划更新、来源撤回、成员或权限改变都会在后续核验中使旧依据不可继续提交或收取。学生先保存自己的改动，再查看最新建议并明确更新依据，不自动套用新建议。上游暂不可达时保留学生自己的草稿与照片，隐藏无法核验的同伴正文，暂不提交或收取。已被浏览器收到的内容不能召回。

提交和收取检查当前依据及本地版本；收取前再核验一次，事务中也检查分享仍有效，避免核验结束后撤回分享仍建立下一稿。来源 RPC 期间本地退出也会阻止交接响应。收取后的正常输入清单保留当时依据和作者计划，供批阅来源追溯；原教师成绩及反馈不由同伴档位覆盖。

## 接口与配置

- 学生预览：`GET /api/student/peer-revisions/:roundId`；创建/加入使用现有 `POST /api/student/revisions`，增加 `peerRoundId`、`expectedHash`，加入已有草稿还需 `expectedRevision` 与 `attachConfirmed`。
- 原修订保存、上传、提交、撤回、重置依据、教师退回/收取和后续批阅接口继续使用；同伴依据更新必须提交当前 `peerBasisHash`。
- 互批机器接口：`POST /api/integrations/writeascend/revision-basis`，使用既有独立交换凭据。可选 `PEER_SERVICE` 为来源 Worker 指向互批的服务绑定；互批的反向来源状态检查仍使用 `SOURCE_SERVICE` 或固定 HTTPS 来源。
- 不增加浏览器可读密钥或强制收费模型配置。公网配置、真实账号及正式学校目录尚未启用。

Daily 仍为 22 文件集成包，新增本轮作者核验能力。实际本机源码经 SHA 预检安装，快照为 `audit/private/daily-bridge-2026-10-16T23-53-27-372Z`；没有修改正式环境变量、重启正式服务或写入正式名册。五条源码安装/回滚路径已验证，旧版本 fixture 使用固定 Git 提交，避免随 HEAD 改变而误标版本。
