## 教师操作主线

1. 复用上次设置，或选择已建立的写作任务。题目、班级、年级、满分、字数和标准摘要始终可见；全部字段可展开修改。
2. 进入收作业。优先支持“先选学生 → 拍照”和二维码批量两条路径；无二维码 OCR 产生候选，异常集中核对。学生、稿次和页码不因切换选择而改变。
3. 对收齐的稿件一键批阅，显示真实后台状态；已成功的步骤不因刷新或失败重试而重复运行。
4. 对照原稿核对完整报告，修改、保存、导出；需要发布时，再确认学生归属和发布版本。
5. 学生从自己的账户查看已发布反馈，再进行自主修订。互批在独立学生项目中使用同一篇教师评价标准。

原来的直接上传和私人一键批改入口继续可用，不强制所有老师先完成学校班级任务。学校任务与学生公开结果使用权威名单和稳定身份，不能用私人名册名称猜测账号。

## 视觉与交互约束

- 背景使用浅灰，内容使用白色卡片、细边框和一套强调色；减少大圆角、强阴影、玻璃效果、装饰性英文和冗余说明。主要内容在桌面保持稳定阅读宽度。
- 主要标题 24–28px，正文与操作标签通常 14–16px，次要说明通常 12–13px；输入字体在手机保持 16px，避免聚焦时系统自动放大。
- 常用题目默认收为摘要，上传保持明显。展开、收起不清空教师修改；缺少写作要求时保持表单可编辑。
- 每个工作区域只有明确的主要下一步；危险重发、替换页面及发布有具体对象和后果，普通保存和查看不重复索要确认。
- 手机按钮以至少 44px 高的触控区域为项目目标；输入框有持续可见的标签，键盘焦点明显，重要操作不只依赖图标或颜色。
- 普通文本以至少 4.5:1 对比度为目标，警告和错误同时给出文字。依据：[W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。44px 采用增强触控目标作为本项目设计标准，不声称其为全部 WCAG AA 要求；参见 [W3C 触控目标说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html)。
- 一线老师不需要看到数据库、队列、密钥绑定等实现术语；管理员配置、模型诊断和历史版本放到相应管理位置。
- 屏幕样式与原 A4 报告分开。不能因为网页字号或卡片改动，改变打印内容、导出栏目或评分计算。

## 本轮已实施

首页增加可展开的本次写作摘要，保留完整表单和原批改函数；收紧账号、任务和存档入口，减少多段说明。增加教师界面共用的颜色、字号、边框、焦点和触控规则；只在屏幕生效，原打印样式不变。

实际 390×844 的合成云端工作区中，复用设置时拍照/批量上传按钮完整位于固定底部操作栏上方。正文编辑经收起和重新展开仍保留；375、390、768、1440px 宽度无整体横向溢出；首页可见按钮高度至少 44px，首页次要正文与背景对比度测得 4.81:1。只对检查过的元素作此结论，不代表全站已通过无障碍认证。

8 组浏览器流程通过，结果与脚本摘要见 [检查记录](verification/ui-review-browser.json)。自动流程见 `scripts/qa/ui-quality.cjs`；本机审查图为 `output/ui-home-mobile.png`、`output/ui-home-desktop.png`。主要报告、快速入口、批量暂停重试、云端续批、预选学生拍照和扫码收取仍须随每一轮相关修改回归。

## 用户追加授权后的实际改造

用户进一步明确：最初 GitHub 的 UI 可抛弃，最终报告也可全面优化。统一报告组件已替换旧的重复实现，教师批阅、班级关联报告、打印与历史预览共用一套表现层。六部分主要内容继续保留；版式调整为清晰的姓名/班级、总分与维度、编号内容区、原句/建议修改对照、改写示范和参考范文，补充 AI 辅助批阅说明。手机采用单列纠错，打印沿用 A4、边距、字号与行距设置，原稿选项支持完整多页图片。

完整工作台改为简洁的阶段导航，常用报告操作直接显示。此前的悬浮网格按钮、玻璃渐变、装饰性大圆角与强阴影不再决定新界面。学生身份关联以后台已确认稿次为准；报告列表不通过同名或序号重新推断归属。

验收仍以实际浏览器、打印文件与测试记录为准，不因视觉重写就把真实手机、真实手写识别、正式云端迁移或学生发布标记完成。
